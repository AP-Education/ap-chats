# 0006. Приватний StarMe всередині DM і груп

Людина викликає StarMe у своїй переписці згадкою `@StarMe`, дією «Запитати StarMe» для одного чи кількох повідомлень або відповіддю на власне приватне повідомлення. Питання і відповіді видно лише тому, хто викликав асистента, у тій самій стрічці DM або каналу. Звичайна переписка не запускає AI.

Composer показує «Приватно зі StarMe · Лише для вас». Наступні повідомлення залишаються приватними до явної дії «Повернутися до чату». Аудиторія зберігається разом із чернеткою в localStorage, окремо для identity, workspace і channel, навіть коли текст порожній. Публікація відповіді не вимикає приватний режим. Приватні запити не можна відкладати в розклад.

## Доступ і зберігання

`chat_messages.assistant_owner_member_id` визначає власника обміну. До публікації повідомлення доступне лише цьому активному учаснику розмови; роль менеджера не відкриває чужі приватні обміни. Posting визначає власника за автентифікованим автором/делегованим правом, а не за ID із клієнта. Поле запиту `assistant: true`, згадка зарезервованого бота або reply на доступне приватне повідомлення зберігають приватну аудиторію. Редагування вже публічного повідомлення у виклик StarMe заборонене: новий приватний запит створюють через composer.

History, прямий ID, reply/context, StarMe context, inbox, unread, push і доступ до вкладень застосовують видимість у запитах до БД. Приватні повідомлення не пересилаються, не закріплюються й не отримують спільних реакцій. Вони мають окремі внутрішні події; relay надсилає звичайні socket-події лише власнику після повторної перевірки поточного доступу. Публічні notification/push handlers цих приватних подій не обробляють. Статус thinking/failure також бачить лише автор запиту.

Глобальний `channel_entries.seq` задає порядок усіх записів; видима історія може мати пропуски. Приватні записи не змінюють спільний `channels.updated_at` і `last_public_entry_seq`, не створюють спільні unread/mention badges чи push. Власник бачить свій приватний preview; інші учасники отримують останній доступний їм запис.

## «Зробити моїм»

Дія доступна власнику лише для справжньої відповіді асистента. `POST .../messages/:messageId/make-own` під блокуванням розмови повторно перевіряє право писати, залишає той самий message ID і текст, змінює автора на людину та ставить `published_at`. Reply, цитата та вибраний приватний контекст від'єднуються. Запис отримує новий публічний seq і час публікації: його бачать як нове повідомлення навіть співрозмовники, які вже прочитали історію після приватної відповіді. Приватний оригінал замінюється; окремої копії немає. Питання та решта приватного обміну залишаються прихованими.

Повторний або конкурентний запит повертає вже опубліковане повідомлення без дубля й повторної події. `assistant_question_id` зберігає походження відповіді незалежно від нового автора/nonce, а `assistant_original_seq` — її місце у приватному AI-контексті власника. Після публікації повторний виклик того самого питання не генерує нову відповідь. Клієнт оновлює history та inbox; cache не дублює ID при зміні seq.

## Інтеграція

Клієнт проєктує доступну власнику відповідь асистента у блок `star-me`, зберігаючи сумісність API з попередніми клієнтами. Ідентифікатор питання береться з reply, коли він доступний. Реєстр блоків показує його через компонент StarMe, спільний зі станами очікування й помилки. Канонічний текст у `markdown` дає змогу відображати блок без міграції зберігання. Позначки `privateToMe` і `assistantAnswer` залишаються джерелом аудиторії та походження відповіді. Після «Зробити моїм» клієнт прибирає блок і приватну позначку, тому відповідь стає звичайним повідомленням людини.

DM і канали використовують ту саму conversation extension та workspace самої розмови. Репозиторій згадок дозволяє активний зарезервований subject `bot:star-me` у людському DM без участі бота в ньому; бот з таким самим display name винятку не має. StarMe не додається до channelMemberships і не отримує самостійного права читати DM. Окремий DM із ботом залишається забороненим.

AI отримує токен автора запиту, доступні йому спільні повідомлення і лише його приватний обмін. Відповідь від бота публікується на повторно перевіреному праві автора запиту відповідно до ADR 0001; контент і вкладення залишаються канонічними за ADR 0002. Токен не записується в повідомлення або чергу. Extension запитує відповідь після підтвердженого posting; закриття клієнта до цього виклику може залишити питання без відповіді. Durable запуск потребує окремого рішення.

## Міграція й перевірки

Явний приватний намір `assistant` запускає обробку підтвердженого питання ще до завантаження списку учасників після reload. Згадки й відповіді продовжують перевіряти ідентифікатор бота. Browser regression затримує members API, надсилає збережену приватну чернетку й очікує відповідь до розблокування members.

Міграція 0035 додає аудиторію, походження відповіді, публікацію та спільний останній seq із backfill. Старі, вже спільні повідомлення залишаються спільними. Перед увімкненням нового клієнта необхідно оновити всі API readers і workers: старі читачі історії не вміють фільтрувати приватну аудиторію. Rolling coexistence зі старими readers не підтримується.

PostgreSQL integration tests перевіряють DM, групи, менеджера, прямі ID, контекст, вкладення, unread/push/inbox, owner-only realtime/status, публікацію, конкурентні повтори й відкликання доступу. Browser QA використовує окремі сесії учасників і production composer/actions; phone Chromium має 4x CPU і trusted long press. Окремі iOS WKWebView та Android WebView wrappers виконують scripted DOM сценарій; це не перевірка фізичних жестів, production OIDC або зовнішнього AI.
