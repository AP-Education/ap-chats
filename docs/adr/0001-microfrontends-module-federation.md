# 0001. Мікрофронтенди на Module Federation

## Рішення

Продукти підключаються до одного host-а як Module Federation remote-и. Документ один, навігація між ними відбувається в межах SPA, а sider і вхід належать host-у. Підхід MPA зі спільним chrome (`feat/mpa-poc`) відхилено.

## Чому це важливо

- MPA блимає при переході між продуктами, і UX не виправдав очікувань. Ставити лоадер на кожен перехід ми не хотіли.
- MPA потребує централізованого вебсервера і chrome, винесеного в окремий скрипт, а обидві речі приносять власні проблеми.
- Складні обидва підходи, тому ми зосередились лише на MF.
- MF зберігає стан між продуктами (realtime, дзвінок) і вантажить React з antd один раз.

|                                          | MF             | MPA            |
| ---------------------------------------- | -------------- | -------------- |
| Перехід у Chats, desktop / mobile        | 26 / 61 мс     | 846 / 987 мс   |
| Порожні кадри на mobile, перший / сталий | 0 / 0 мс       | 517 / ~50 мс   |
| Холодний старт Chats, desktop / mobile   | 2016 / 3824 мс | 1610 / 2391 мс |

Повні вимірювання лежать у `docs/mf-vs-mpa.md` у гілці `feat/mpa-poc`.

## Важливо (пов'язаний технічний борг)

Холодний старт важчий: на 25% на desktop і на 60% на mobile. Це свідомий обмін на миттєві переходи. Версії singleton-ів (react, antd, router, `@ap/shell-sdk`) у host-а і remote-ів мають збігатися.
