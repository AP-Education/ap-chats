# 0003. Приватні обкладинки відео

## Рішення

Відео залишається файлом користувача в `attachments` за ADR 0002. Під час завершення upload сервер для MP4 і WebM розміром до 64 MiB пробує створити WebP обкладинку до 960 px, ThumbHash і визначити розміри та тривалість. Необовʼязкові `hasThumbnail` і `duration` розширюють метадані вкладення; старі повідомлення й клієнти продовжують працювати.

Оригінал надходить із приватного storage в обмежений тимчасовий файл. FFprobe та FFmpeg читають тільки локальний файл через дозволені файлові протоколи й демультиплексори MP4/WebM. Обмежені байти, роздільність, час, кількість потоків та розмір результату. Обкладинки й фото ділять один слот обробки з обмеженою чергою. Помилка декодування не блокує відправлення відео: воно лишається файловою карткою з відтворенням і завантаженням.

Обкладинка лежить у приватному `${objectKey}.preview.webp` і видаляється наявним cleanup разом з оригіналом. URL видається лише для вкладення живого повідомлення після перевірки чинного доступу ADR 0001. Запит thumbnail без наявної обкладинки повертає 404 і не віддає оригінал під виглядом картинки.

Стрічка запитує обкладинку лише поблизу viewport і не завантажує відео до натискання. Відтворення лишається у наявному медіапереглядачі. Коли обкладинка недоступна, назва, кнопка відтворення й завантаження залишаються доступними. Контейнер, який браузер не декодує, можна завантажити.

Відео з обкладинкою показуємо однією медіабульбашкою без дублювання файлової картки. Тривалість, розмір і окрема кнопка завантаження розташовані поверх кадру; назва доступна в підказці та доступних назвах кнопок. Без підпису час повідомлення розташований у кутку останнього медіавкладення; з підписом закриває його текст. Старі відео без обкладинки залишаються файловими картками.

Переглядач використовує системні елементи керування відео. Поки оригінал завантажується, показує обкладинку й стан очікування; відмова autoplay залишає явну кнопку запуску. Після помилки можна повторно отримати URL і відкрити той самий файл або завантажити його. Сусідні відео галереї запитують оригінали лише після переходу на них; при виході зі слайда відтворення зупиняється.

## Чому це важливо

Превʼю через окремий video елемент у кожному повідомленні змушує телефон читати оригінали, декодувати кілька відео й залежати від поведінки preload у WebView. Маленьке приватне зображення дає передбачувану витрату трафіку та спільний механізм доступу з фото.

Сервер є джерелом метаданих, тому клієнт не може видати сторонню URL або файл за обкладинку. Поля не змінюють структуру повідомлення, повторно використовуються при пересиланні та не потребують міграції таблиць, де attachments уже збережені знімком.

## Обмеження

Існуючі вкладення не обробляємо масово; вони показуються як раніше. Для файлів понад 64 MiB обкладинку не створюємо. Підтримка контейнера не гарантує підтримки конкретного кодека браузером. FFmpeg входить до runtime образу API та середовища CI. Якщо виміри покажуть перевантаження completion, обробку можна перенести в окремий воркер із тим самим форматом похідного файла.
