# 0005. Голосові повідомлення як вкладення

Голосове повідомлення є файлом користувача в `attachments` відповідно до ADR 0002. Наявні upload reservation, перевірка прав писати, claim, posting nonce, пересилання, завантаження й очищення залишаються спільними. Окремої таблиці чи колонки голосових повідомлень немає.

Клієнт завершує завантаження з `kind: "voice"`. Сервер читає не більше 20 MiB, розбирає контейнер MP4/M4A, WebM, Ogg або WAV та перевіряє один аудіотрек без відео. Тривалість обчислюється за часовими мітками пакетів, зокрема для MediaRecorder WebM без заголовка Duration; MIME, розширення й передана клієнтом тривалість не є джерелом правди. Ліміт запису — від 0,5 секунди до 10 хвилин з допуском 0,5 секунди на завершальний пакет кодека. Перевірене вкладення отримує `voice: { durationMs }`. Старі клієнти продовжують показувати його як аудіофайл. Повторне завершення звичайного файла не може перетворити його на голосове.

Браузер обирає підтримуваний MediaRecorder формат і записує лише після явного натискання та дозволу. Чернетка запису живе в поточному composer. Закриття, зміна акаунта або розмови звільняє мікрофон; вихід у фон завершує запис для прослуховування, не надсилаючи його. Пауза не входить у тривалість. Порожній або надто короткий запис відхиляється.

У мобільній оболонці мікрофоном, дозволами, аудіосесією та файлом володіє `voice-messages`, записуючи AAC/M4A через expo-audio. Через міст передаються лише непрозорий ідентифікатор файла, метадані та стан. URI, токени і базові байти не є частиною публічного контракту запису. Надсилання використовує той самий upload API з нативним auth та частинами файла; upload queue вебклієнта володіє порядком відправлення, повторенням і nonce. Нативний файл прив'язаний до початкового workspace/каналу і видаляється після передачі повідомлення, скасування чи завершення сесії. Дзвінок перериває запис; запис не запускається під час активного дзвінка і не переналаштовує його аудіосесію.

Запис, прослуховування та підтвердження надсилання — окремі дії. У повідомленні є пауза, перемотування, тривалість, швидкість і завантаження. Одночасно відтворюється один аудіозапис. Право читати файл перевіряється спільним attachment API за ADR 0001; серверні перевірки під час completion і posting не замінюються клієнтськими прапорцями.

Емулятори перевіряють запис, файли, дозволи та UI; переривання справжнім телефонним дзвінком на фізичних iOS/Android пристроях потребує окремої перевірки. Відсутній дозвіл, старий shell без voice-моста й втрата локального файла мають явний стан помилки та не запускають автоматичне надсилання.
