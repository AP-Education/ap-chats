# Голосові повідомлення

У порожньому composer утримуйте круглу кнопку мікрофона, щоб записати голосове, і відпустіть для надсилання. Проведіть ліворуч для скасування або вгору для фіксації запису без утримання. Схема жестів відповідає [Telegram Tips](https://t.me/s/TelegramTips/116). Короткий тап або клавіатура одразу починають запис без утримання; модального вікна й додаткової кнопки «Почати» немає. Після фіксації можна призупинити й продовжити, зупинити для прослуховування, видалити або надіслати. Поле повідомлення зберігається, а ненадіслана відповідь утримує свій контекст. Ліміти: десять хвилин, 20 MiB, мінімум 0,5 секунди. Втрата жесту чи запізнілий дозвіл не спричиняють автоматичного надсилання.

Після надсилання голосове має власний плеєр із паузою, перемотуванням, тривалістю, швидкістю 1×/1,5×/2× та завантаженням. Початок іншого аудіо призупиняє попереднє. Повідомлення використовує звичайну чергу файлів і posting nonce: помилка завантаження лишає повторення, а повторний Send не створює другого голосового. При зміні розмови чи акаунта ненадісланий запис скасовується. Вихід у фон завершує його для прослуховування, без автоматичного надсилання.

У браузері працює MediaRecorder з перевіркою підтримуваного формату. Native записує AAC/M4A через expo-audio; через міст ідуть лише стан і непрозорий ідентифікатор файла. Черга зберігає початкову розмову, native uploader читає обмежені частини через FileHandle і передає їх через expo/fetch, без створення React Native Blob з ArrayBuffer. Після завершення або скасування локальний файл видаляється. При перезавантаженні застосунку локальний дескриптор запису відновити неможливо: потрібно записати повідомлення повторно.

`POST …/uploads/:id/complete` приймає необов'язкове `kind: "voice"`. Сервер перевіряє власника, чинне право писати, розмір, контейнер, один аудіотрек без відео й тривалість за пакетами. Лише після цього додається `attachment.voice.durationMs`. Клієнт не може задати тривалість чи підмінити тип перейменуванням файла. Готовий звичайний файл не можна повторним complete перетворити на голосове. Читання, claim, пересилання і cleanup використовують спільні перевірки вкладень. ADR 0005 описує рішення; міграція БД не потрібна.

Перевірки:

```sh
pnpm test:api
pnpm test:web
pnpm --filter @ap-chats/mobile test
pnpm --filter @ap-chats/web exec playwright install chromium webkit
pnpm --filter @ap-chats/web test:voice
docker compose --env-file /dev/null -f infra/docker-compose.voice-test.yml up -d --wait
pnpm build
node --import tsx test/voice.integration.mts
docker compose --env-file /dev/null -f infra/docker-compose.voice-test.yml down
```

Браузерні тести використовують синтетичний аудіопотік і справжній MediaRecorder, composer, чергу, outbox та серверний parser. Є desktop, 390 px і 320 px із 4× CPU та WebKit phone. Нативний стенд і процедура локального Android/iOS тестування описані в [test/voice-native](../test/voice-native/README.md). Переривання справжнім телефонним дзвінком і фізичні аудіомаршрути перевіряються окремо на пристроях.

У CI Chromium працює на Linux, а WebKit MediaRecorder — в окремому macOS job із медіастеком Apple. Це відповідає [рекомендації Playwright для Safari та медіа](https://playwright.dev/docs/browsers#webkit). Відсутність підтримуваного формату перевіряється окремим UI-сценарієм до запиту мікрофона.
